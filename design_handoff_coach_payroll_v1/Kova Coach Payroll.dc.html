Coach payroll — tightened
Every mechanic stays: autosave-as-you-tap, per-day submit, the names and hours sheets, Other line items, period finalize, admin review and close. What changes is the anatomy. Every tile now reads the same way — label top-left, value bottom-left, action bottom-right, one reserved caption line — so nothing sits at a different height from its neighbour. The floating checkmark that half-hung off each tile's edge is gone; state is carried by the tile's own fill and border, the convention already used in My Fitness. The staff bar drops from four tabs to three: Requests and 1:1 Nutrition are both "pay that isn't logged daily," so they became one Extra pay screen, and My Entries → Log, Pay Stubs → My Pay.

What this changes in code
PayrollTile.js — drop TileCheckmark and its absolute positioning entirely; state becomes fill + border + an 11px inline tick. Anatomy goes label-top / value-bottom-left / control-bottom-right / reserved caption, so TILE_HEIGHT can stay static without paddingBottom:28 reserving space for a floating badge.
PayrollDateNav.js — the 150×72 date tile, the two arrows, and the calendar button all collapse into one component: a 5-day window inside the 14-day Thursday→Wednesday period, arrows stepping the selected day, the window sliding so the selected day sits centre once it's past day 3 and holding still again at the tail. windowStart = clamp(selectedIndex - 2, 0, 9) — no scroll container, no PayrollDatePicker, no new data (datesWithEntries and submittedDates already carry the dot states).
PayrollTabBar.js — four tabs to three, equal-width flex instead of a horizontal ScrollView. can_view_nutrition now gates the Nutrition segment inside Extra pay rather than a whole tab, so a coach without it sees Requests only and no empty tab.
nutrition.js + requests.js — merge into one route with a two-segment switch. Both keep their own loaders; nothing about assignments, approvals, or approveRequest changes.
report.js — restyle only, no new data. "Day 9 of 14" is elapsed days in the period, computed from the period's own start and end — deliberately not days logged, since most coaches don't work every day and the bar shouldn't imply a daily submit is owed.
Admin, five tabs kept — the closed-periods split was a deliberate call, so this pass only restyles. Two behavioural notes: the report's PayrollBottomSheet becomes an inline side panel on web (the sheet stays on native), and the share bars are each staff member's total over the period leader's — no new query, just computeTotalsByStaff output it already has.
